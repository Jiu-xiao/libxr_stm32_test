# libxr_stm32_test

STM32 工程的 LibXR 编译测试 / LibXR build tests for STM32 projects

## 1. 板子与平台 / Boards and Platform

仓库中的每个目录是一个由 STM32CubeMX 生成的 STM32 工程，用于检查指定版本的 LibXR 能否在不同芯片、不同系统和不同工具链下编译。LibXR 由测试脚本获取：对每个目标运行 `libxr` 包提供的 `xr_cubemx_cfg`，生成入口源文件并把 LibXR 作为子模块加入 `Middlewares/Third_Party/LibXR`，再检出指定的版本。表中的 MCU、外设和系统取自各目录 `.ioc` 文件中的配置。

| 目录 / Directory | MCU | 外设 / Peripherals | 系统 / System |
| --- | --- | --- | --- |
| `Atom-STM32G431KB` | STM32G431KB | FDCAN1 | FreeRTOS |
| `BluePill-STM32F103C8-CAN` | STM32F103RC | CAN | FreeRTOS |
| `BluePill-STM32F103C8-USB` | STM32F103RC | USB | 无 / none |
| `BoringTech_STM32F302CB` | STM32F302CB | USB, CAN | FreeRTOS |
| `DevC-STM32F407IG` | STM32F407IG | USB OTG FS, CAN1, CAN2 | FreeRTOS |
| `DevC-STM32F407IG-ThreadX` | STM32F407IG | USB OTG FS, CAN1, CAN2 | ThreadX |
| `MC02-STM32H723VG` | STM32H723VG | USB OTG HS, FDCAN1 to FDCAN3 | FreeRTOS |
| `NUCLEO-STM32F072RB` | STM32F072RB | USB | 无 / none |
| `STM32G0B1` | STM32G0B1CB | USB DRD FS, FDCAN1, FDCAN2 | 无 / none |
| `STM32L031F4` | STM32L031F4 | LPUART1 | 无 / none |
| `WeActStudio_Mini_STM32F401RC` | STM32F401RC | USB OTG FS | FreeRTOS |
| `WeActStudio_Mini_STM32H750` | STM32H750VB | USB OTG FS, FDCAN1, FDCAN2 | FreeRTOS |

Each directory in the repository is an STM32 project generated by STM32CubeMX and is used to check whether a given version of LibXR builds for different chips, systems and toolchains. The test script fetches LibXR: for each target it runs `xr_cubemx_cfg`, provided by the `libxr` package, which generates the entry source and adds LibXR as a submodule in `Middlewares/Third_Party/LibXR`, and then checks out the requested version. The MCU, peripherals and system in the table are taken from the configuration in the `.ioc` file of each directory.

## 2. 配置一览 / Configurations

每个目标依次用下表的四种工具链配置构建，构建目录位于目标目录下。

| 构建目录 / Build directory | 工具链 / Toolchain | C 库 / C library |
| --- | --- | --- |
| `build-gcc` | GNU Arm Embedded (`cmake/gcc-arm-none-eabi.cmake`) | nano |
| `build-clang-STARM_HYBRID` | ST Arm Clang (`cmake/starm-clang.cmake`, `STARM_TOOLCHAIN_CONFIG=STARM_HYBRID`) | hybrid |
| `build-clang-STARM_NEWLIB` | ST Arm Clang (`STARM_TOOLCHAIN_CONFIG=STARM_NEWLIB`) | newlib |
| `build-clang-STARM_PICOLIBC` | ST Arm Clang (`STARM_TOOLCHAIN_CONFIG=STARM_PICOLIBC`) | picolibc |

Each target is built in turn with the four toolchain configurations in the table above, and the build directories are created inside the target directory.

## 3. 构建 / Build

### Linux

Linux 下使用镜像 `ghcr.io/xrobot-org/docker-image-stm32:main`，镜像提供 CMake、Ninja、GNU Arm Embedded 14.2 和 ST Arm Clang。`libxr` 包提供 `xr_cubemx_cfg` 和 `xr_stm32_toolchain_switch`，其版本与被测的 LibXR 对应，测试 LibXR 6.0.0 使用 `libxr` 6.0.0。`test.sh` 的参数依次为 LibXR 的分支、标签或提交（默认 `dev`）和目标目录（默认全部目标）。

```bash
git clone https://github.com/xrobot-org/libxr_stm32_test.git
cd libxr_stm32_test
docker run --rm -v "$PWD:/work" -w /work ghcr.io/xrobot-org/docker-image-stm32:main \
  bash -c "git config --global --add safe.directory '*' && pip install libxr==6.0.0 && ./test.sh dev DevC-STM32F407IG MC02-STM32H723VG BluePill-STM32F103C8-USB"
```

`test.sh` 对每个目标依次运行 `xr_cubemx_cfg`，在 `Middlewares/Third_Party/LibXR` 中执行 `git fetch origin <ref>` 并检出获取到的提交，再完成第 2 节的四次构建；全部结束后列出生成的 ELF 文件。`restore.sh` 删除所有目标目录，并用 `git restore`、`git reset --hard` 和 `git clean -fd` 把仓库还原到提交状态，同时清除 `.git/modules`。

On Linux the image `ghcr.io/xrobot-org/docker-image-stm32:main` provides CMake, Ninja, GNU Arm Embedded 14.2 and ST Arm Clang. The `libxr` package provides `xr_cubemx_cfg` and `xr_stm32_toolchain_switch`; its version corresponds to the LibXR under test, and testing LibXR 6.0.0 uses `libxr` 6.0.0. The arguments of `test.sh` are the LibXR branch, tag or commit (default `dev`) followed by the target directories (default all targets).

For each target `test.sh` runs `xr_cubemx_cfg`, executes `git fetch origin <ref>` in `Middlewares/Third_Party/LibXR`, checks out the fetched commit and performs the four builds of section 2; when everything is done it lists the generated ELF files. `restore.sh` deletes all target directories, restores the repository to the committed state with `git restore`, `git reset --hard` and `git clean -fd`, and clears `.git/modules`.

### Windows

基于 STM32Cube for VS Code 插件下载的包，配置 `PATH`：

```powershell
C:\Users\$env:USERNAME\AppData\Local\stm32cube\bundles\gnu-tools-for-stm32\13.3.1+st.9\bin;C:\Users\$env:USERNAME\AppData\Local\stm32cube\bundles\gnu-gdb-for-stm32\13.3.1+st.10\bin;C:\Users\$env:USERNAME\AppData\Local\stm32cube\bundles\st-arm-clang\19.1.6+st.8\bin;C:\Users\$env:USERNAME\AppData\Local\stm32cube\bundles\st-arm-clangd\19.1.2+st.3\bin;C:\Users\$env:USERNAME\AppData\Local\stm32cube\bundles\stlink-gdbserver\7.10.0+st.3\bin;C:\Users\$env:USERNAME\AppData\Local\stm32cube\bundles\stlink-server\2.1.1+st.7\bin;C:\Users\$env:USERNAME\AppData\Local\stm32cube\bundles\cmake\4.0.1+st.3\bin;C:\Users\$env:USERNAME\AppData\Local\stm32cube\bundles\ninja\1.12.1+st.9\bin
```

设置环境变量：

```powershell
$env:GCC_TOOLCHAIN_ROOT = "C:\Users\$env:USERNAME\AppData\Local\stm32cube\bundles\gnu-tools-for-stm32\13.3.1+st.9\bin"
$env:CLANG_GCC_CMSIS_COMPILER = "C:\Users\$env:USERNAME\AppData\Local\stm32cube\bundles\st-arm-clang\19.1.6+st.8"
```

`test.ps1` 的参数 `-Branch`（默认 `dev`）和 `-Target`（目标目录，默认全部目标）与 `test.sh` 的参数对应：

```powershell
pip install libxr==6.0.0
.\test.ps1 -Branch dev -Target DevC-STM32F407IG
```

The packages downloaded by the STM32Cube for VS Code extension are used, with `PATH` set as in the first PowerShell block and the environment variables `GCC_TOOLCHAIN_ROOT` and `CLANG_GCC_CMSIS_COMPILER` pointing at the GNU Arm Embedded `bin` directory and the ST Arm Clang directory. The parameters `-Branch` (default `dev`) and `-Target` (target directories, default all targets) of `test.ps1` correspond to the arguments of `test.sh`.

## 4. 烧录与运行 / Flash and Run

工程仅用于编译测试，不保证能在 STM32 上正常运行。构建产物为各构建目录中的 ELF 文件。

The projects are only used for build tests and are not guaranteed to run on an STM32. The build output is the ELF file in each build directory.
